# コーディングルール

## 基本方針

- Python の既存構成と型注釈を尊重し、変更範囲を担当責務に限定します。
- 公開クラスやサービスの引数・戻り値・例外条件を docstring で説明します。
- 外部 API、DB、ファイル I/O はサービスまたは専用の初期化境界に集約します。
- 環境変数名、DB カラム名、API の識別子は既存の命名を確認してから追加します。
- 秘密情報、アクセストークン、個人情報をログへ出力しません。

## エラーとトランザクション

- DB 書き込みは失敗時に rollback し、例外を握りつぶさず呼び出し側へ伝えます。
- 利用者向けの失敗と運用者向けの詳細ログを分離します。
- 外部サービスの例外は、再試行可能性とユーザーへの表示内容を考慮して扱います。
- HTTP ルートでは認証・許可を確認してから対象データを取得します。

## 設定とファイル

- 設定値は環境変数または共有設定から取得し、コードに秘密値を埋め込みません。
- JSON やワークフローを読む場合は UTF-8 と構造検証を前提にします。
- パスは設定値を基準に解決し、ユーザー入力をそのままファイルパスとして連結しません。
- キャッシュを導入する場合はキー、更新、無効化、プロセス境界を明記します。

## 変更時の確認

- 実装変更前に対応する設計文書と既存の近隣実装を確認します。
- モデル変更には Alembic の変更を伴わせます。
- 設定名を変更する場合は Compose、README、コード、運用環境の参照を同時に確認します。
