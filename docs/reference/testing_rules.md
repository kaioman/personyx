# テストルール

## 現状

既存のテストファイルは未作成です。本文書は現行のテスト実績ではなく、今後追加するテストの最低基準を定義します。テスト作成後、本項の内容は修正します。

## 優先するテスト

- **単体テスト**: スピンタックス展開、ペルソナの DB 優先・ファイルフォールバック、設定値の解析、ユーザー解決を検証します。
- **サービステスト**: OAuth2 コールバックの成功・失敗、画像メタデータ保存時の commit と rollback、ComfyUI 応答異常を検証します。
- **Web テスト**: ログイン、state 不在、ログアウト、未ログイン時のギャラリー、ユーザー別画像絞り込み、フィルター条件を検証します。
- **Bot テスト**: Bot 自身のメッセージ除外、Cog からサービスへの委譲、コマンド入力の妥当性、外部応答失敗時の表示を検証します。
- **DB テスト**: 外部キー、ユニーク制約、有効状態、削除時の関連動作、Alembic の upgrade を検証します。
- **結合テスト**: PostgreSQL、Web、Bot のユーザー識別子が同じユーザーを指し、生成画像がギャラリーへ表示されることを検証します。

## テスト原則

- 外部 API はモックまたはテスト用アダプターで置き換え、テストをネットワーク状態に依存させません。
- テストごとに DB 状態を分離し、共有キャッシュとセッションを明示的に初期化・破棄します。
- 認証テストでは秘密情報を実値で使わず、state、許可ホスト、ユーザー境界を検証します。
- ファイル生成テストは一時ディレクトリを使い、リポジトリの生成画像を変更しません。
- 不具合修正には、再発条件を表す最小の回帰テストを追加します。

## 要設計変更の検証

- ペルソナディレクトリ変数名を統一する場合は、Compose から Bot の読み込みまでの結合テストを追加します。
- `FLASK_SECRET_KEY` を本番必須にする場合は、未設定時に起動を拒否し、設定時に再起動後もセッションを復号できることを検証します。
- 画像ファイルと DB の不整合対策を決めた場合は、各失敗順序と再実行結果を検証します。
