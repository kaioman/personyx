# 命名ルール

## Python

- モジュール、関数、変数は `snake_case` とします。
- クラスは `PascalCase` とします。
- 定数は `UPPER_SNAKE_CASE` とします。
- Boolean は `is_`、`has_`、`can_` など意味が判別できる接頭辞を使います。
- サービス名は担当するユースケースや外部境界を表す名詞に `Service` を付けます。
- Flask の Blueprint は機能名に `_bp` を付けます。

## DB と外部識別子

- テーブル名、カラム名、制約名は既存の `snake_case` を踏襲します。
- SQLAlchemy モデルのクラス名は既存モデルとの互換性を優先します。
- 外部認証の識別子は `provider` と `provider_user_id` の組み合わせで表します。
- ユーザー、Bot プロファイル、ペルソナを指す ID は、対象の境界を名前から判別できるようにします。

## 設定

- 環境変数は大文字の `UPPER_SNAKE_CASE` とします。
- 設定名は Compose、コード、ドキュメントで一致させます。
- `PERSONA_CHAT_DIR` と `PERSONA_CAHT_DIR` のような綴り違いを新規に作らず、既存利用状況を確認して統一します。

## 文書

- Markdown ファイル名は小文字の `snake_case` を基本とします。
- 見出しは責務または判断事項を表し、実装固有名だけで章を構成しません。
- 業務上の不変条件、未確定事項、要設計変更事項は明示的に区別します。
