# 業務ルール

## ユーザーと認証

- アプリ内ユーザーは `Users` で管理し、外部認証アカウントは `UserAccounts` として分離します。
- Discord OAuth2 の成功後、既存アカウントを検索し、なければユーザーと認証アカウントを登録します。
- 未ログインユーザーは画像ギャラリーの対象データを取得できません。
- Bot が画像を DB に保存するには、Discord アカウントが Web で一度ログイン済みである必要があります。

## ペルソナとプロファイル

- ユーザーに有効な Bot プロファイル割り当てがあり、グループとプロファイルも有効な場合に、そのプロファイルのペルソナを利用します。
- DB から該当ペルソナを解決できない場合は、設定ファイルのペルソナをフォールバックとして利用します。
- ペルソナ設定はユーザー単位でキャッシュされます。設定変更を即時反映する運用を採用する場合は、キャッシュ無効化の設計が必要です。
- 定型文に含まれるスピンタックスは選択肢からランダムに展開します。閉じ括弧がない入力は破壊せずに扱います。

## 会話と画像

- Bot は自身のメッセージを処理対象にせず、チャンネルとユーザーの組み合わせで会話状態を扱います。
- `/dressup` はレーティング選択を受け、ペルソナとワークフローに基づいて ComfyUI で画像を生成します。
- 生成画像はファイルとして保存し、ファイル名、レーティング、シーン、プロンプト情報、ユーザー、ペルソナをメタデータとして保存します。
- Web ギャラリーはログインユーザーの画像を新しい順に最大 200 件取得し、レーティングと `scene_id` で絞り込めます。

## データ削除と関連

- ユーザー削除時の認証アカウントやプロファイル割り当ての連鎖削除はモデルと DB 制約に従います。
- ペルソナ削除時に Bot プロファイルの有効ペルソナ参照をどう扱うかは、外部キーの `SET NULL` 方針に合わせます。

## 要設計変更

- 複数セッション間でペルソナ設定を更新する場合のキャッシュ失効条件は未定義です。
- 画像ファイルだけ、または DB レコードだけが残った場合の再同期ルールは未定義です。
- ギャラリーの画像配信ルート自体は設定ディレクトリを配信しますが、ファイル単位の所有者検証をどこまで要求するかは運用上明文化が必要です。
